# catchment

The catchment layer takes a DEM and an outlet and gives the catchment, its river network and the ground the model sits on. It conditions the DEM and routes flow on it through a terrain engine, which is a port (`terrain/`, with its own README). It delineates the catchment, cuts the domain polygons and extracts the streams. It also holds the surfaces of the domain, the routing of water on the cells of the model top, the stream-network criterion on arrays and the French departments used to pick data tiles. The package is a layer because the mesh, the model, the solvers and the results all start from the same ground and the same network, and it knows no solver and no data provider. The DEM arrives as a resolved `dem_path` with its digest and state, and a geology map is read by a function the caller passes as an argument.

The package reads `core` and `schema`, and nothing else of HydroModPy. It is read by `mesh`, `model`, `data`, `solver`, `results`, `calibration`, `workflow`, `config` and `project`. The order of its own parts is in `tests/unit/architecture/catchment_layout.yaml`, and another layer may import only the modules that file lists as public.

The package has nine parts: `administrative/`, `delineation/`, `terrain/`, `algorithms/`, `synthetic/`, `preprocess/`, `drainage/`, `stream_network/` and the three surface modules at its root. The mesh itself is in `hydromodpy/mesh`, and the aquifer geometry, the fields and the forcings are in `hydromodpy/model`. The page of the package lists every module with the first line of its docstring, and it describes the Whitebox backend, the seven steps of a preprocess run and where to add what.
