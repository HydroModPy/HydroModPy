# `hydromodpy/project/examples`

This folder holds what `hmp example` stands on. It has the catalog of shipped examples, the cache their files are fetched into, the install into a workspace and the generator that writes the catalog from a checkout.

`catalog.toml` is generated and ships inside the wheel. It is read with no network, so `hmp example list` never promises what the installed version does not know. A test compares the regenerated bytes with the committed file, so a drift fails the suite. `python -m tools.dev examples manifest` rewrites it.

`manifest.py` reads the catalog (`load_catalog`, `find_entry`) and renders it (`render_catalog`). `blobs.py` is the cache and the download. `install.py` writes one example into a workspace that already has a `data/` folder. `rows.py` flattens an entry into the rows the command prints. `generate.py` holds `WHITELIST` and `write_catalog`.

The cache is keyed by file. Of the 92 MiB that example 04 needs, `DEM_armorican_massif.tif` is 90 MiB. A blob keyed by its sha256 is downloaded once and costs nothing to the next example that reads it. Blobs live at `<cache>/examples/blobs/<sha256[:2]>/<sha256>`, beside the solver binaries.

A file comes from `HMP_EXAMPLES_SOURCE` when it is set, as a URL or a local checkout, and from the release tag of the installed version otherwise. A sha256 that does not match the catalog is a hard failure, and nothing reaches the workspace. An install keeps a destination whose content differs, and `hmp example add --force` overwrites it.

`WHITELIST` has one entry on purpose. Only example 04 runs end to end from a fresh workspace, and a catalog of thirty with one that works is worse than a catalog of one. A project earns a line once it does.
