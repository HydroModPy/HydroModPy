# Synthetic Heterogeneous Boussinesq Comparison

This folder contains the synthetic MF6/Boussinesq comparison scaffold for the
Boussinesq testbed family. The central case is a long recharge-response
demonstrator, not only a smoke test. The campaign now also includes controlled
variants for homogeneous properties, stronger K contrast, recharge forcing,
domain size and topographic gradient.

The case follows the normal simulation path:

1. `geographic.source_mode = "synthetic"` generates the DEM support.
2. `data.geology` loads local synthetic geology polygons.
3. `mesh_catchment` generates a new geology-conformal mesh.
4. The comparison workflow materializes two ordinary simulation TOMLs:
   one MODFLOW 6 reference and one Boussinesq candidate.

No pre-existing mesh is used.

The synthetic geography runtime does not generate a river network. For that
reason this case uses:

```toml
[mesh_catchment]
constraints_mode = "geology_only"
```

The static `examples/data/dem/conceptual_dem.tif` raster is used only as the
reference grid for rasterizing the synthetic geology polygons. The topography
used by the simulation is still generated by `[geographic.synthetic]`.

## Files

- `synthetic_geology_zones.geojson`: three deterministic geology zones.
- `synthetic_geology_zones_small.geojson` and
  `synthetic_geology_zones_large.geojson`: rescaled geology zones for the
  domain-size cases.
- `base_synthetic_patchy_mf6_bouss_transient.toml`: shared 36-month
  recharge-response simulation case.
- `base_synthetic_homogeneous_control.toml`: same geometry and recharge, with
  homogeneous `K` and `Sy`.
- `base_synthetic_patchy_strong_k.toml`: same geometry and recharge, with a
  stronger conductivity contrast.
- `base_synthetic_drainage_low.toml` and
  `base_synthetic_drainage_high.toml`: legacy drainage-sensitivity placeholders.
  They are not included in the current case-1 Boussinesq campaign and their
  drainage conductance is set to zero.
- `base_synthetic_recharge_pulse_48m.toml`: 48-month recharge chronicle with
  two pronounced pulses.
- `base_synthetic_small_domain.toml` and `base_synthetic_large_domain.toml`:
  smaller and larger square domains with rescaled geology and observation
  anchors.
- `base_synthetic_low_slope.toml` and `base_synthetic_high_slope.toml`:
  weak and strong regional topographic gradients.
- `boussinesq_synthetic_patchy_testbed.toml`: Boussinesq-only mesh-resolution
  testbed with coarse/reference/fine regenerated meshes.
- `compare_synthetic_*_mf6_bouss.toml`: one MF6/Boussinesq comparison per
  synthetic case.
- `run_synthetic_comparison_campaign.sh`: WSL campaign launcher that runs the
  comparison TOMLs through the normal HydroModPy CLI.
- `build_synthetic_comparison_synthesis.py`: reporting helper that builds the
  campaign-level HTML index from already generated comparison outputs.

The domain-size cases use separate scaled geology polygons and scaled point
observables. This keeps the geology classes and comparison anchors meaningful
instead of clipping or extrapolating the central-domain geometry.

## Demonstration design

The forcing covers 36 monthly stress periods from September 2020 to August
2023. It includes a normal wet season, one dry year, and one strong recharge
pulse. The case does not use a lateral prescribed head anymore. For the
Boussinesq candidate, the comparison overlay forces the Cauchy drainage
conductance to `0.0 m2/s`: this is the current case-1 configuration, with the
free-surface VI upper obstacle kept strict (`h <= z_top`). The MODFLOW 6
reference can still carry its configured DRN package when the base case uses
one; the Boussinesq candidate does not use that finite-conductance drainage
term.

The transient recharge uses the actual first monthly value at the first stress
period (`first_clim = "first"`). The mean of the 36-month chronicle is used only
inside the steady-state initial-condition workflow.

The transient initial head is generated by the generic steady-state initial
condition workflow:

```toml
[flow.ic]
type = "steady_state"
source = "mean_recharge"
recharge_statistic = "time_mean"
boundary_condition_policy = "first_period"
```

Each solver first runs a same-solver steady solve with the mean recharge of the
36-month chronicle, then reuses that field as the transient initial state.
For Boussinesq, the demonstrator uses the Linux PETSc path: the transient solve
is `runtime_backend = "petsc"` with
`surface_interaction_model = "ts_vi_obstacle"`, PETSc TS Backward Euler and
SNESVI. The auxiliary steady initialization stays in PETSc and uses the
stationary SNESVI obstacle model
`surface_interaction_model = "vi_obstacle"`.

For Boussinesq case 1, the explicit Cauchy drainage conductance is zero. The
PETSc VI upper obstacle is therefore not relaxed: the numerical variable is
bounded by the aquifer top and any top interaction is represented by the
obstacle/complementarity behaviour rather than by
`C * max(h - z_top, 0)`.

single HTML page with one table of active comparisons and does not generate
extra `web_synthesis/cases/*.html` pages or case-level figure grids. The table
links directly to the comparison reports and reports MF6/Boussinesq wall times,
mean head difference percentage, and mean global-outflow difference percentage.

```text

```

The HTML code that renders these individual reports is generic comparison code,
not a synthetic-Boussinesq-specific implementation:

```text
hydromodpy/analysis/comparison/web/
```

and its `comparison_manifest.json`, not by hard-coded HTML logic. The campaign
synthesis only links to the comparison reports generated under
`comparisons/<comparison_id>/web/index.html`.

`examples/projects/10_testbed_workflow/outputs/` are local artifacts. They should
not be committed; commit the TOML inputs, scripts, documentation, report

Current comparison figures are deliberately limited to:

- `case_configuration.png`, shown separately as context;
- one interpolated hydraulic-head field comparison after the first wet season:
  `head_map_wet_year1__fine_raster_map_comparison.png`;
- separate point head chronicles, one figure per observation point;
- `storage_comparison_dashboard.png`, for global storage-rate comparison only;
- `total_inputs_outputs_dashboard.png`, for the sum of external inputs and the
  sum of external outputs.

The comparison HTML does not display budget diagnostics, aggregated outflow
chronicles, non-interpolated head maps, head-field triptychs/difference maps,
runtime bars, or the former dashboard that grouped the five head chronicles on
one figure.

The comparison figures use fixed method-family colors across head and budget
figures: MODFLOW 6 aliases (`modflow6`, `mf6_ref`) are blue, and Boussinesq
aliases (`boussinesq`, `bouss_candidate`) are orange.

Fluxes are compared through physically aligned totals, not raw native process
names. MODFLOW 6 contributes `RCHA`, `DRN` and storage-package budgets. The
Boussinesq comparison reads canonical Zarr `budget/recharge`,
`budget/surface_excess`, `budget/drain` and `budget/well` fields; storage is
computed from head, bottom/top elevation, cell area and storage coefficient.
For the current synthetic case without lateral prescribed head, the Boussinesq
candidate should be read as a strict free-surface obstacle case. Native
`budget/drain` is expected to stay inactive when the zero-conductance overlay
is used; any surface interaction should be interpreted through
`budget/surface_excess` and the global balance.
Balance-implied outflow remains available in the CSV as a diagnostic, but it is
not the primary plotted comparison for this case.

The former global head-chronicle dashboard, extra head-field maps, fine-raster
variants, generic budget diagnostics, native flux graphs and runtime bar figure
are not part of the synthetic comparison view anymore.
